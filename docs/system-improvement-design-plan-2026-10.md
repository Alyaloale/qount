## 1. 定位审查与取舍

QOUNT服务个人账户的长期风险调整后财富增长。当前单账户、单策略的实现应优先解决退出可靠性、必要告警和收益判断；工程任务不成为离线研究的前置。保留现有FastAPI、SQLite、静态前端和执行器。

按单人维护判断必要性：功能应能防止具体交易错误、让异常及时可见，或帮助判断扣费后是否值得继续。能低频人工完成的操作先保留人工方式。

| 能力 | 必要性与时机 | 个人开发者需要做到的程度 |
| --- | --- | --- |
| 可靠退出与已有保护 | 当前必须 | 修复已复现的到期退出缺陷，保留原订单身份、实际持仓核对和原生止损 |
| 严重异常通知 | 无人值守时必须 | 复用一个可靠通知通道，报告需要介入的失败；无需普通状态推送或告警平台 |
| 投入资金与损失边界 | 当前必须明确 | 以现有规则及owner明确决定约束真实风险；独立资金分配和自动停机系统可以后做 |
| 真实净损益与盈利研究 | 必须持续关注 | 有成交即核对价格、费用、资金费和损益；当前先跑已有最小对照，不等待新绩效系统 |
| 页面状态解释 | 附带修正，完整功能可后做 | 修正误导文案、展示时间和已知错误；拒绝原因及最近决策随接口改动补充即可 |
| 关键状态备份与恢复 | 必要，可先手动 | 发布前备份并验证能恢复，不要求先建立定时备份或异机灾备系统 |
| 跨年日历 | 已补齐至2028，后续按官方公布维护 | 收录休市、提前收市与纽约夏令时；未收录年份不猜测新仓日期 |
| 自动接管、多账户、完整决策历史等 | 当前不必要 | 真实操作或排障需求出现后再做，不因计划列出便启动 |

近期退出缺陷、必要通知、相关页面解释与跨年日历均已交付，备份按变更需要人工执行。风险边界及盈利判断始终保留，但不把它们扩展为整套平台建设。

上述删减只针对计划范围。未知归属、不重复下单、原生止损、时间正确性、真实成本和生产权限继续作为底线。

## 2. 近期实现范围

工程先修已复现的退出缺陷和通知故障；状态解释随相关改动补齐。研究同步推进，不等待工程清单全部完成。

| 工作 | 最小改动 | 完成依据 |
| --- | --- | --- |
| 到期退出（已发布） | 调整 `manage` 中退出判断与income查询的依赖 | 故障回归通过；到期且income超时、明细不可用仍可退出，未知订单不重复提交 |
| 必要通知（已发布） | 精确修复目录所有者，独立observer接入阻塞/失败/停止/收据过期 | 去重和恢复回归通过；既有重试服务成功，刷新会话后实际验收消息首次投递获接受 |
| 状态解释（已发布） | 实际timer/服务状态、通知投递、已有拒绝原因及最近正式决策 | 失败、过期和完整停止可区分；缺运行来源不宣称运行正常 |
| 最小恢复能力（本次完成） | 手动对执行库、宏观状态及账户历史做一致备份与一次隔离恢复 | 恢复数据可读且身份一致，不覆盖真实成交或重放订单 |
| 跨年支持（已发布） | 收录2027/2028休市与提前收市；未知年份不阻塞已知风险退出或跳过续期失败全平 | 跨年特征/下次入场、夏令时、未知年份保护与退出回归通过，旧2026完整回放保持 |

### 到期退出

主要修改 [macro_live.py](../src/qount/execution/macro_live.py)。先核对实际持仓归属、未决订单和已存储退出意图，再执行已确定的到期退出；income、ETF特征和公开行情查询失败不应阻止这一动作。资金费未知不写成零，续期失败仍按原规则全平。

订单结果未知时查询原client ID。部分退出保留保护和恢复信息，确认真实空仓后才清理相关止损。可延后的成交明细采集失败单独报告，不成为风险退出的额外前置。

验证聚焦到期+income超时、订单超时不重复提交、部分退出和未知归属四类场景；已有相关回归继续复用。

### 通知与异常处理

复用 `notifications/` 的存储、去重和重试。修正必要非密目录的所有者与读取/遍历权限，保留私密文件权限，不递归放宽仓库或扩大服务能力；验证采用实际服务约束。

优先通知需要处理的异常，同一未解决原因合并，恢复后再提示；成交/平仓确认按实际使用需要补充。普通周末等待和无信号不默认推送。网络或通知落库失败不得阻塞止损与退出，不输出凭据或签名URL。

HALT继续表示整个周期停止，页面明确持仓管理也停止、已有原生止损保留。外部部分减仓等无法解释的数量变化继续阻塞并通知，核对原订单和真实成交后再按已有授权处理，不自动补回数量或认领外部交易。本轮不为此增加自动接管流程。

日报权限问题随同目录修复核对，但恢复旧日报内容、研究采集和清理历史死信不进入近期交付；不为清除失败状态恢复已停用timer。页面ETF日报与市场情报任务是不同来源，保留真实缺失状态。

### 页面与决策解释

在现有 `/account/one-atr` 中透出已计算的 `rejections`、`candidate_count` 和决策资金，保留最近正式决策摘要及其时间，避免下一小时等待状态抹去原因。复用现有结果或状态文件，不先建决策数据库、历史查询接口或专用观测文件。

页面按真实来源区分当前周期、最近决策、账户持仓和保护时点。由既有采集入口补少量必要的timer/服务状态，复用账户观测来源；API不按页面请求调用交易所。不具备实际状态来源时显示“最近收据/当前调度未核实”，不能把 `auto_live` 收据直接等同于服务仍在运行。

保留 `/health` 的API存活语义。需要检测交易周期停止时复用已有独立采集入口；未覆盖VPS整机失联就明确保留这个限制，不据此另建监控服务。

### 备份与日历

执行SQLite使用backup API，与 `macro-state.json` 在现有周期锁保护下取得一致边界；账户库保留各自时点和覆盖信息。相关变更发布前备份，在隔离目录做一次恢复核对；恢复后必须只读核对交易所持仓与未决订单，不能自动启用交易。凭据不进入备份，同机副本只解决误操作恢复。

跨年支持已按[NYSE官方日历](https://www.nyse.com/trade/hours-calendars)收录至2028年。2027-12-31保持正常交易（2028元旦为周六，NYSE不补休），2028-07-03为13:00提前收市。纽约时区处理夏令时；日线仍保守等至16:00才可用，跨年读取上一有效交易日。未知日历禁止新入场，持仓先执行风险管理，续期日历未知则全平；其余日历相关检查阻塞并保留原生保护，不宣称完整管理成功。原成本、期限与止损规则保持。

## 3. 并行研究

沿用[既有研究安排](personal-system-consolidation-plan.md#下一步研究先解释净收益与本金风险)，已完成固定其他条件、均值回归最长7天与21天的基础/双成本对照。7天基础收益−0.15%，原21天+29.42%；双成本两者均−6.13%。不支持直接缩短期限，实盘不变；机制与限制见[结果](personal-system-consolidation-plan.md#均值回归持有期限对照已执行)。

复用已有窗口、缓存和回放，重点判断闭合/截尾利润贡献、资金费、净收益、回撤与实际敞口。7天版本按期退出，不继续续期；小时收盘MDD仍不代表盘中最坏损失。只对影响结论的交易补必要执行压力检查。

结果仍属已消费历史，不重新宣称独立OOS，也不据此自动换实盘参数。首笔实际成交出现时复用现有记录核对价格、数量和成本，研究无需等待它发生。不新增登记、连续日报、固定观察期或大规模搜索。

## 4. 有触发条件再做的能力

| 能力 | 启动条件与最小范围 |
| --- | --- |
| 暂停新入场、继续管理持仓 | owner确有这一操作需求时增加单独开关，保留HALT原义，核对已经提交或结果未知的订单 |
| 已闭合交易的独立净损益 | 出现真实归属成交后，先按回合计算费用、资金费和损益；后续新仓不应让之前可核实的闭合结果失效 |
| 策略本金与收益率 | 明确资金分配、划转和估值时点后再计算；此前只报可确认损益，不补造净值 |
| 账户损失约束 | 先用现有数据测回撤和连续损失；owner明确阈值、触发动作与恢复规则后写入现有风控，数据不足时先约定绝对资金边界 |
| 输入预热或有限重试 | 实测耗时逼近窗口或发现可恢复输入失败；保留同一决策身份与90秒上限，未知订单先查询，不补过期单 |
| 决策历史、记录筛选与导出 | 实际排障或对账反复需要时补最小查询；旧数据缺口随输出保留 |
| 异机备份、多币种或其他账户接入 | 数据损失风险或实际资产管理需求要求时明确目的地、估值和权限边界，再做对应实现 |

明确投入和可承受损失是当前必要的风险决策，不能用尚未建设自动停机功能作为推迟理由，也不能把当前50%压力预算当作最大损失保证。自动化动作在阈值和规则确定后再实现；本次审查不自行改变现行策略或资金边界。账户风险和策略研究可以先用现有数据测量。

按[项目规则](project-rules.md)运行受影响模块及关键故障回归，文档只维护必要设计。生产修复沿用 [current.md](current.md) 已有授权；未覆盖的资金、控制或调度改变，先完成可审阅实现与验证，再确认具体变化。前端继续只读，真实发送按既有明确发送授权执行。

发布核对真实仓位和未决单，保护执行及账户原始记录；代码回退不覆盖真实状态，也不恢复退役交易器。分别报告已实现、已测试和已发布，未发生实际成交就不声称实盘链路已经验证。
