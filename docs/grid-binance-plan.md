## 0. 核心判断(先说结论,别自欺)

> **网格不创造方向 alpha。它是一层「分批买入 + 高抛低吸」的执行外壳——
> 本质是卖波动率 / 提供流动性。在震荡市跑赢持有,在单边趋势里跑输持有,
> 在深熊里满仓被套。**

把话说死,免得后面自我感动:

| 行情 | 网格表现 | 对比「纯持有」 |
|---|---|---|
| **宽幅震荡** | 反复高抛低吸,每次穿越赚一格 | **跑赢**(这是网格唯一的主场) |
| **温和上涨** | 边涨边卖,仓位越涨越轻 | **跑输**(卖飞了,踏空上半场) |
| **单边急涨(飞网)** | 很快清仓变 U,踏空 | **大幅跑输**(Trailing Up 是补救) |
| **单边下跌(破网)** | 越跌越买,满仓被套 | 打平或略差(都亏,但你满仓) |

所以本设计真正要回答的**唯一 kill-test 不是「网格能不能赚钱」,而是:**

> **「网格 + 趋势滤网」能否跑赢「200MA 之上就持有(buy-and-hold-above-MA)」这条基线?**

这和线 A 的 L6 反复撞的结论同型——*没有任何 path-dependent exit 跑得赢「持有到期」基线*。
网格是一种 path-dependent exit,默认它**有罪**,要用回测证明它在扣费后、在多个市场
regime 上、相对持有基线**有正增量**,才允许进 paper。

三条会要命的现实(线 A 已用真金白银撞过):

1. **maker 成本墙(L4/L6 反复出现)**:网格全靠 limit 单(maker)成交。一旦价格**跳空穿过**
   你的挂单价、或你被迫用 taker 追单,`required_maker_fill` 一掉,单格利润立刻被成本吃光。
   网格的盈利前提是「绝大多数成交以 maker 价成交」,这必须在回测里**显式建模**,不能假设 100% maker。
2. **单边做多 = 你在下注该资产长期向上**。网格只决定「怎么买/怎么卖」,不决定「该不该持有这个币」。
   选错标的(进入长期下行的山寨),再好的网格也只是优雅地慢性亏损。**标的选择 = 趋势滤网的责任,
   不是网格的责任。**
3. **「单格利润 > 手续费」是必要非充分**。即使每格净赚,若价格不在区间里来回穿越(穿越次数 = 0),
   收益就是 0;若价格单边走掉,收益是负的持有损失。**收益 = 单格净利 × 穿越次数 − 持有方向损益**,
   穿越次数由波动率决定,不可控。

## 1. 策略机制(三阶段 → 模块)

### 1.1 单边做多网格(Long-Only Grid)

- **永不主动做空。** 只在价格下跌时分批挂买单(Buy Limit);买单成交后,在其上方一格挂对应卖单
  (Sell Limit);卖单成交后,在原买价处重新挂回买单。如此形成一组「买—卖」配对的循环。
- **利润沉淀两种模式(可配置):**
  - `settle_quote`(屯 U):每完成一对买卖,利润以 USDT 落袋,本金恒定。适合不看长期暴涨、只收割波动。
  - `settle_base`(屯币):卖出量略小于买入量,把利润留成币,长期累积底仓。适合长期看多、愿意承担回撤。
- 任一时刻的持仓 = 「已成交买单」减「已成交卖单」的净累积;价格越靠近下限,持仓越重(越接近满仓)。

### 1.2 趋势滤网(Trend Filter)——四态状态机

用大级别趋势决定**网格是否运行、是否继续买入**。指标:`SMA200`(日线)为主,`MACD` 作辅助确认。
不直接用裸穿越,要**确认**(连续 N 根收盘在均线一侧,或 MACD 柱反转)以防假突破来回打脸。

```text
状态机(每根日线收盘评估一次,日内只执行不切状态):

  ┌─────────────┐  price>SMA200 且确认       ┌──────────────┐
  │   PAUSED    │ ───────────────────────▶  │   ACTIVE     │
  │ (深熊,停买) │                            │ (满血运行)    │
  └─────────────┘  ◀───────────────────────  └──────────────┘
        ▲          price<SMA200 且确认(翻空)        │
        │                                           │ price<SMA200 但未确认
        │                                           ▼
        │          反弹站回 SMA200 且确认     ┌──────────────┐
        └──────────────────────────────────  │  DERISK      │
                                              │ (只卖不买)    │
                                              └──────────────┘
```

- `ACTIVE`:买卖双向都挂,网格满血运行。
- `DERISK`(跌破均线但未确认翻空):**只挂卖单平掉已有持仓、不再挂新买单**,防止在下跌中段继续接飞刀。
- `PAUSED`(确认翻空 / 深熊):撤掉所有买单,网格冻结。已有底仓按 `settle_base`/全局止损规则处理。
- 站回均线并确认 → 重新进入 `ACTIVE`,按当前价重新布网(见 §3.2 Trailing Up 复用同一逻辑)。

> 明确:趋势滤网是**风控门**,不是 alpha 来源。它的作用是把网格从「深熊满仓被套」
> 这种尾部里拉出来,以**牺牲部分反弹收益**换**回撤可控**。是否值得,§6 的分年归因要给数。

### 1.3 标的与计价

- 起步只做 **1 个高流动性主标的**(默认 `BTC/USDT`,备选 `ETH/USDT`)。**先把一个标的的成本/成交模型
  跑通,再谈多标的并行。** 多标的不是广度,是 N 倍运维和 N 倍踩坑面。
- 计价 USDT;现货账户,**不加杠杆**(网格 + 杠杆 = 破网时强平,直接归零,本设计明确禁止)。

## 2. 数学模型与参数

### 2.1 等比网格(Geometric Grid)

加密资产价格跨度大(3 万 ↔ 12 万),**必须用等比网格**:每格之间的百分比固定,涨到高位每格赚的
百分比不变。给定下限 `L`、上限 `U`、格数 `n`:

```text
公比         q     = (U / L) ^ (1 / n)
单格步长     step  = q − 1                         （每格毛利率,百分比）
第 k 条网格价 P_k  = L · q^k        k = 0,1,...,n
```

反过来,先定**单格步长** `step`,再算需要多少格:

```text
n = ln(U / L) / ln(1 + step)
```

### 2.2 手续费摩擦与单格利润下限(maker 口径,必须修正用户初稿)

用户初稿按**市价单 taker 0.1%、往返 0.2%、要求单格 > 0.5%**。**修正**:网格是挂限价单,
正常应以 **maker** 成交,Binance 现货费率(2026 口径,随 VIP 等级下降):

| 成交方式 | 单边费率(无 BNB) | 含 BNB 抵扣(-25%) | 往返成本 |
|---|---|---|---|
| Maker(限价被动成交) | 0.1000% | 0.0750% | **0.15%** |
| Taker(吃单/追单) | 0.1000% | 0.0750% | 0.15% |

> Binance 现货 maker/taker 基础同为 0.1%,VIP1+ 才拉开差距。**关键不是 maker 比 taker 便宜多少,
> 而是网格逻辑天然只产生限价单 → 你应当几乎全程吃 maker;真正的风险是「跳空导致被迫 taker 追单」
> (见 §0 第 1 条 maker 墙)。**

**单格净利下限(硬约束):**

```text
net_per_grid = step − fee_buy − fee_sell − slippage_buffer
要求:        net_per_grid ≥ 0.30%   （安全垫,而非用户初稿的 0.5% taker 口径）

推荐区间:    step ∈ [0.5%, 1.5%]
  - step < 0.5%:净利薄,一旦混入 taker 或滑点立刻转负 → 拒绝
  - step > 1.5%:每格毛利厚但穿越次数锐减,资金利用率低 → 仅适合极高波动标的
默认:        step = 1.0%（含 BNB maker 往返 0.15% 后,net ≈ 0.85%/格）
```

### 2.3 资金分配与单格金额

```text
n              = 网格条数 = ln(U/L) / ln(1+step)
grid_capital   = 总资金 × (1 − reserve_ratio)        # 入网资金,reserve_ratio 见 §3.1,默认 0.20
per_grid_quote = grid_capital / n                     # 每格买单金额(USDT，等额下注)
per_grid_base  = per_grid_quote / P_k                 # 每格买入的币量(随价格变)
```

> 等额 USDT 下注(每格花同样多的钱)在等比网格上意味着**越跌买越多的币**,自动摊低均价,
> 是和「越跌越买摊薄」一致的。

### 2.4 预期收益估算(诚实版)

```text
周期收益 ≈ net_per_grid × N_crossings  +  inventory_pnl
          └─ 网格收割(正) ────────┘    └─ 持仓方向损益(正负不定)─┘

  N_crossings = 统计期内价格穿越网格的总次数（强烈依赖波动率,不可控、不可预测）
  inventory_pnl = 期末持仓按市价的浮盈浮亏（趋势上涨为正、下跌为负）
```

- **网格收割项**恒为正,但大小由波动率决定;**持仓项**是方向暴露,牛市帮你、熊市坑你。
- 这正是为什么 §6 的 kill-test 必须把**网格收割项**单独剥离出来,跟「纯持有」对比——否则牛市里
  网格的正收益全是 `inventory_pnl`(持有本来就赚的),网格那层可能根本是负贡献(卖飞了)。

### 2.5 边界参数:下限/上限怎么定

- **下限 `L`(最低防线)**:放在强支撑下方——上一轮熊市底部、或重要筹码密集区下沿。跌破 `L` = 破网(§3.1)。
- **上限 `U`(止盈逃顶)**:放在历史前高 / 预期牛市顶。突破 `U` = 飞网(§3.2)。
- 工程上 `L/U` 不是「猜顶猜底」,而是**风控边界**:`L` 决定你愿意满仓套多深,`U` 决定你愿意踏空多高。
  二者 + `step` 三选二即定全网格,第三个由 §2.1 公式推出。

## 3. 风控护城河(极端行情应对)

### 3.1 破网处理(跌破下限 `L`)——满仓被套

```text
触发:price < L
状态:网格已满仓(grid_capital 全部转成币),账面深套
预备队:reserve_ratio = 20% 总资金,始终留在场外,不参与常规网格
动用条件(两者同时,机械化,非拍脑袋):
  (a) price < L  且
  (b) Fear & Greed Index < 15（极度恐慌）
动作:用预备队分批(再细分 3–4 笔)市价/限价买入,摊低均价
       —— 预备队是一次性子弹,打完即止,不补充、不循环
全局止损硬线(优先级最高,压过抄底欲望):
  若 price < L × (1 − max_drawdown_floor)，例如再跌 35%，
  无条件停止一切买入,进入 PAUSED,记录并告警。宁可认亏出局,不归零。
```

> **预备队不是「无限抄底」。** 它是**一次性**的、有明确触发条件和明确耗尽边界的子弹。
> 破网 + 趋势 PAUSED 的组合意味着:基本面/趋势都坏了,此时该认的是「这一轮赌该资产长期向上赌错了」,
> 全局止损线兜底,而不是用预备队接无底洞。

### 3.2 飞网处理(突破上限 `U`)——踏空

```text
触发:price > U
状态:网格卖光,持仓 ≈ 0,全是 U,踏空上涨
应对:启用 Trailing Up（网格上移）
  1. 撤销当前所有挂单（尤其是下方永远不会成交的买单）
  2. 以当前价为锚,按同一 step、同一 n 重新计算新区间 [L', U']
     （L' = price / q^(n/2) 、U' = price · q^(n/2)，把当前价放回网格中部）
  3. 在新区间重新布网,恢复 ACTIVE
约束:Trailing Up 只在 **趋势滤网 = ACTIVE(price>SMA200)** 时允许;
       否则可能在假突破后追在山顶 → 要求和 §1.2 状态机联动确认。
```

> 对称地,可设计 **Trailing Down**(向下移网)用于温和阴跌——但**默认关闭**:向下追网 = 主动接飞刀,
> 与趋势滤网的初衷冲突,只在明确震荡 regime 下由人工开启。

### 3.3 风控优先级(冲突时谁说了算)

```text
全局止损硬线  >  趋势滤网 PAUSED  >  破网抄底  >  飞网 Trailing Up  >  常规网格收割
```

任何时候高优先级规则触发,低优先级动作让路。这条链写进 `risk_engine`,是唯一仲裁者。

**新增模块(建议):**

建议都落在独立的 `src/qount/grid/` 包下,**不改线 A 同名生产文件**:

| 模块 | 职责 | 说明 |
|---|---|---|

**订单生命周期(单格闭环):**

```text
挂 BuyLimit@P_k  ──成交──▶  立即挂 SellLimit@P_{k+1}  ──成交──▶  实现 net_per_grid，
                                                                  重新挂 BuyLimit@P_k
若 SellLimit 长期不成交(价格继续跌):持仓累积、均价被 §2.3 的等额下注自动摊低
对账:每轮主循环核对「交易所真实挂单」== 「网格应有挂单」,漂移则补挂/撤单(幂等)
```

> **对账(reconcile)是网格系统的命根子**:断线、漏成交回报、部分成交都会让本地状态和交易所
> 真实挂单漂移。主循环必须每轮拉取真实挂单与持仓,和「网格理论状态」对齐——这块的工程量
> 比网格数学本身大得多,也是实盘事故高发区。

## 5. 默认参数表(起步配置)

```text
标的             BTC/USDT (现货,无杠杆)
区间             L / U 按当时支撑/前高定,默认跨度 U/L ≈ 2.0
单格步长 step    1.0%
网格条数 n       ≈ 70   （= ln(2)/ln(1.01)）
单格净利下限     ≥ 0.30%   （maker 往返 0.15% + 滑点垫后,实际 ≈ 0.85%）
利润沉淀模式     settle_quote（屯 U）起步,验证后再考虑 settle_base
趋势滤网         SMA200 日线 + MACD 确认;确认 N = 2 根日线收盘
预备队 reserve   总资金的 20%（场外,一次性子弹)
破网抄底触发     price < L 且 Fear&Greed < 15
全局止损硬线     price < L × (1 − 0.35)  → PAUSED,无条件停买
Trailing Up      仅 ACTIVE 状态启用;Trailing Down 默认关闭
费率假设         maker 0.075%（含 BNB 抵扣);回测必须额外建模 taker 滑出
live             实验性,所有者按进度自行开关;起步先 paper 验证
```

## 6. 验证计划:上线前建议过的 kill-test(本线工程理性,非线 A 纪律)

实验线不强制走线 A 那套冻结门控,但这套 kill-test 是**「怎么知道它真的 work」的方法**,
强烈建议照做:**先回测证伪 → 再 paper → 再小资金 live**。借了线 A 的方法(DSR/PBO/持有基线),
不借它的「不过就永久止盈」。

### S1 — 核心 kill-test:vs 持有基线(最便宜、先做)

```text
基线:      buy-and-hold-above-SMA200（趋势滤网 ON 时满仓持有,OFF 时空仓)
对照:      同滤网下的网格策略
数据:      BTC/USDT 日线+小时线,覆盖 ≥3 个完整 regime:
           2021 牛 / 2022 熊 / 2023–24 震荡复苏 / 2025–26 近窗
判生死:    扣费(maker 口径)后,网格的【网格收割项】相对基线的【增量】是否显著为正?
           —— 必须分年归因,证明不是「牛市里 inventory_pnl 抬轿、网格层其实负贡献」
若不过:    网格相对持有无正增量 → 诚实承认这套复杂度是负价值,回到「站上均线就持有」即可;
           实验线可以选择换标的/换 regime 继续试,但别自欺说网格层在赚钱
```

> 这是整个设计的生死命门,直接对标 L6 的「path-dependent exit vs hold-to-close」结论。
> **若网格跑不赢「站上均线就持有」,这套系统的全部复杂度都是负价值。**

### S2 — maker fill 压力测试(成本墙,L4/L6 同型)

```text
在 S1 回测里显式建模 maker 成交率:
  - 正常震荡:limit 单大概率 maker 成交
  - 急跌/跳空:挂单被跳过 / 被迫 taker 追 → 把这部分成交按 taker + 滑点计
读数:      required_maker_fill（要维持正收益所需的最低 maker 成交比例)
判生死:    required_maker_fill 在现实可达范围(经验上 ≤ 0.9)且仍正 → 过;
           若需 >0.95 maker 才正 → 撞 maker 墙,证伪(与 L4/L6 同结局)
```

### S3 — 参数稳健性(反过拟合)

```text
- step / n / 区间宽度做网格扫描,看收益对参数的敏感度（陡峭=过拟合)
- 借线 A 现成的 DSR / PBO / purged-CV harness(无副作用纯函数)给「最佳参数」打多重检验折扣
- 区间 L/U 的选择本身是一种「事后选址」,要用滚动/样本外窗口验证不偷看未来
判生死:    最佳参数在 OOS 不崩、DSR/PBO 过 → 进 paper;否则继续证伪或停
```

### S4 — paper(纸面实盘)

```text
- 真实行情、真实挂单/撤单/成交回报、真实对账,但不动真钱
- 重点验证工程:断线重连、部分成交、对账漂移、状态机切换时的挂单清理
- 跑满 ≥1 个完整震荡周期 + 至少经历一次 DERISK/PAUSED 切换
判生死:    paper 实现盈利与回测一致、无对账事故 → 才谈 live(需所有者显式授权)
```

### S5 — live(实验性,所有者按进度自行决定)

```text
- 小资金灰度、单标的、严格全局止损线（实验线可接受用真金小额验证)
- 复用现有 live guard / runtime halt / 日内权益隔离作安全网,但开关由所有者掌握,非永久关闭
```

## 7. 实施路线与硬约束

**路线(一轮只改一处,先写单测):**

1. `grid_engine`:等比网格数学 + 买卖配对状态机 + 单格净利校验(纯函数,易单测)。
2. `trend_filter`:SMA200/MACD 四态状态机 + 确认逻辑。
3. S1 回测:接历史 K 线,跑 vs 持有基线的分年归因 → **这一步决定要不要继续**。
4. S2/S3:maker fill 压力 + DSR/PBO/purged-CV 反过拟合。
5. `executor` 扩限价 maker 下单 + 对账;`risk_engine` 扩破网/飞网/止损优先级链。
6. `grid_orchestrator` 串起来 → S4 paper。
7. (需授权)S5 live 灰度。

**保留约束(实验线可放松大部分,但这几条是安全/诚实底线,建议守住):**

- **不加杠杆**(现货网格 + 杠杆 = 破网强平归零)——这是安全底线,不是线 A 纪律。
- **全局止损硬线优先级最高**,压过任何抄底/补仓欲望。
- **预备队是一次性子弹**,有触发条件、有耗尽边界,不无限循环抄底。
- **maker fill 与成本必须显式建模**,不假设 100% maker;撞 maker 墙就诚实承认、别硬上。
- live 开关、是否追盈利、是否上真金——**由所有者按实验进度决定**,不受线 A 永久关闭约束。
- 验证可在 **Mac 本地**直接跑(本地 unittest → 回测 → artifact),**不强制走 WSL 生产真相链路**;
  变更写回**本线文档**([grid-binance-plan.md](grid-binance-plan.md) /
  [grid-binance-optim.md](grid-binance-optim.md)),**不写 `current.md` / `update-log.md`**。

## 8. 一句话总结

> 网格是**执行外壳,不是 alpha**。它在震荡市靠高抛低吸赚波动率收割,代价是趋势市跑输持有、
> 深熊满仓被套。趋势滤网把最坏的熊市尾部切掉,破网/飞网/全局止损兜住极端。
> **整套设计的生死,押在一个 kill-test 上:扣费后、分 regime 看,它能不能跑赢「站上 200 日线就持有」。
> 过了就放手做(这是实验线,可追盈利、可上 paper/live);过不了,就诚实承认网格层没在赚钱,
> 别用复杂度自我感动。** 这条线和线 A(qount CTA 研究)隔离,纪律各自独立。
