## 0. 核心判断(先把四个方向分类,别一视同仁)

> 四个优化**不是同一性质**。把它们当「都是改进」一起上,是最容易出事的做法。

| 方向 | 本质 | 诚实定性 | 优先级 |
|---|---|---|---|
| **③ ATR 弹性间距** | 把间距绑定波动率 = 仓位的波动率目标化 | **真 edge**。直接攻 v0.1 最致命的破网尾部;且与线 A 的 L1 反波动率定权同源(有证据背书) | **先做** |
| **② 无限追踪网格** | 让网格随趋势上爬 | **真改进,但有 whipsaw 税**。把策略从「均值回归」掺入「趋势跟随」,牛市救踏空、震荡市被反复打脸 | 次做 |
| **① 高斯资金分配** | 资金向当前价集中 | **对「震荡」的杠杆化下注**。震荡市放大收益,但削弱深跌摊薄能力、与破网抄底哲学冲突;1.5–2× 只在主场成立 | 三做 |
| **④ 生息叠加** | 闲置 U 生息 + 永续网格 | **分两层**:Tier-1(闲 U 活期理财)是干净的免费收益;Tier-2(用生息资产当永续保证金)是**风险叠加 + 资金费率方向被线 A 证据反驳**,门控最严 | 拆开,Tier-1 早做 / Tier-2 最后 |

三条贯穿全篇的诚实底线:

1. **①②③ 全部是「网格形状」的调制,不改变网格不创造方向 alpha 这个本质**(v0.1 §0)。
   它们让收割更高效或更抗揍,但生死命门仍是「扣费后能否跑赢站上 200MA 就持有」——优化只是
   让这条线更可能过,不是绕过它。
2. **「无风险」三个字在加密里基本是自欺**(尤其 ④)。Simple Earn = 交易所托管/对手方风险(FTX 教训);
   Aave = 合约风险 + 清算风险 + 稳定币脱锚风险。本文件不允许把 5–10% 年化叫「无风险」。
3. **风险不是线性相加,危机里同时引爆**。④ 把网格满仓被套 + 资金费率反向 + DeFi 挤兑 + 稳定币
   承压绑在一根绳上——「一鱼两吃」在黑天鹅里变「一鱼两亏」。

## 1. 统一抽象:把 ①②③ 收敛成一个「网格形状生成器」

①②③ 各改网格的一个维度,**若各写各的会互相打架**(高斯把资金集中在价格附近、ATR 又要把下方
拉宽、追踪又在移动中心)。所以先定义一个**统一参数化的网格形状函数**,三个优化都是它的入参:

```text
G(center, atr, vol_pct, trend_state) → [ (price_k, weight_k, side_k) ]  k = -m..+m

  center      当前网格中心(② 追踪让它随趋势爬升)
  atr         真实波动幅度(③ 决定每格间距)
  vol_pct     波动率分位(③ 决定下方是否非对称拉宽)
  trend_state v0.1 §1.2 状态机(ACTIVE/DERISK/PAUSED,门控 ② 追踪和买单)

价格阶梯(③ ATR 弹性 + 非对称):
  base_step   = clamp( k_atr · ATR / center ,  step_min , step_max )     # 间距 ∝ 波动率
  step_up_j   = base_step                                                # 上方正常
  step_down_j = base_step · (1 + asym · vol_pct)                         # 下方暴跌时拉宽(③ 防接刀)
  P_{+j} = center · Π_{i≤j}(1+step_up_i)   ;   P_{-j} = center / Π_{i≤j}(1+step_down_i)

资金权重(① 高斯,在 log 价格空间,以 center 为均值):
  w_k ∝ exp( −(ln P_k − ln center)² / (2 σ_alloc²) )                     # 近中心密、边缘稀
  归一化 Σw_k = 1 ;  per_grid_quote_k = deployable_capital · w_k
  σ_uniform → ∞ 时退化为 v0.1 等额分配(基线,可一键关掉 ①)
```

> 这样 ①②③ 是同一个函数的三组旋钮,`σ_alloc→∞ & k_atr 固定 & center 不动` 就**精确退化回 v0.1**,
> 保证每个优化能**单独开关、单独 kill-test**(满足「一轮只改一处」)。

## 2. ① 高斯/非对称资金分配

### 设计

```text
痛点:    等额分配 → 大量资金挂在远端常年不成交,震荡期资金利用率低。
优化:    资金按 log 价格空间的高斯分布,向 center 集中。
  σ_alloc 控制集中度。映射「内层 X% 价格带承载 70% 资金」:
     选 σ_alloc 使 ∫_{中心±X%} w = 0.70 ;默认内 1/3 网格 ≈ 70% 资金、外 2/3 ≈ 30%。
  下注金额:per_grid_quote_k = deployable_capital · w_k(近密远稀)
  远端稀疏格 = 「插针摸奖」:极端行情才成交,单格金额小、步长大(配合 ③),博一次暴利。
效果(诚实版): 震荡市资金周转 ↑ → 同本金收益率可提升 ~1.5–2×,但仅在价格反复穿越 center 的前提下。
```

### 诚实风险(必须写进 kill-test)

- **这是对「价格留在 center 附近」的杠杆化下注**。价格一旦单边走掉,密集资金被快速消耗、剩下稀疏
  尾部,**和 v0.1 等额相比可能跑输**(你在错误的一侧重仓了)。1.5–2× 是主场数字,不是全天候。
- **与破网抄底(v0.1 §3.1)哲学冲突**:高斯把资金集中在价格附近 = **越深跌、单格资金越少** =
  暴跌时摊薄成本的能力**变弱**。你不能同时「向当前价集中提高周转」又「在深渊留厚弹药抄底」。
  v0.1 的 20% 场外预备队部分对冲了这个矛盾,但网格内分布仍是「底部偏薄」,必须明确接受这个取舍。
- **center 必须随价格移动**(否则一波动后密集区全成交、你长期困在稀疏尾部)→ 强制和 ② 追踪耦合。

### kill-test(S-①)

```text
对照:  v0.1 等额分配 vs 高斯分配,同区间同 step,扣费。
判生死: 高斯在【震荡 regime】风险调整收益(Sharpe/Calmar)显著 > 等额,
        且在【趋势/暴跌 regime】不显著更差(尤其最大回撤不放大)。
        —— 不能只看震荡期收益翻倍就上,要看它在熊市有没有因为底部偏薄而崩。
```

## 3. ② 无限追踪网格(Trailing Grid / 弹性边界)

### 设计

v0.1 §3.2 的 Trailing Up 是「飞网后整体重布」;本优化把它做成**连续滚动窗口**(毛毛虫式):

```text
痛点:    单边网格涨破上限 → 全部卖飞,后续大牛与你无关。
优化:    固定 n 格的窗口随新高向上滚动:
  触发:  最新价创窗口新高(且趋势 = ACTIVE,且站稳确认 ≥ confirm_bars,防假突破)
  动作:  撤销最底部一格买单(释放 U)→ 在最上方新建一对买卖区间 → window 上移一格
  结果:  网格区间像毛毛虫随多头趋势上爬,永不出现「无币可卖」的踏空。
对称项:  Trailing Down 默认关闭(向下追 = 主动接飞刀,与趋势滤网初衷冲突);
        仅在明确震荡 regime 由人工开启。
```

### 诚实风险

- **追踪 = 给策略掺入趋势跟随,自带 whipsaw 税**。每次「站稳确认后上移」,若紧接着反转(牛市陷阱),
  你已把买梯抬高、用更高成本基接下跌——这是趋势跟随经典的反复止损打脸,搬到网格上一样存在。
- **「永不踏空」只在趋势持续时成立**。震荡掺假突破的市道里,追踪频繁上移又被打回 = 持续小亏。
  所以**追踪速度必须被门控**:用 `confirm_bars` 确认 + 按 ATR(③)而非单 tick 触发,降低 whipsaw 频率。
- 资金中性:释放底部 U、部署顶部,净占用大致不变(✓);但每次滚动产生撤单 + 新挂单 = 额外 maker
  成交依赖,撞 maker 墙时追踪越频繁越吃成本。

### kill-test(S-②)

```text
对照:  v0.1 固定边界(飞网整体重布) vs 连续追踪窗口。
判生死: 在【趋势 regime】追踪显著挽回踏空收益,
        且在【震荡 regime】whipsaw 损耗不把震荡期收益吃掉(净 ≥ 基线)。
关键读数: trailing_whipsaw_cost(每次上移后 confirm_bars 内反转的频率 × 成本),
        以及 required_maker_fill 是否因追踪换手升高而恶化。
```

## 4. ③ ATR 弹性网格间距(波动率自适应)——四者中最该先做

### 设计

```text
痛点:    固定间距遇黑天鹅急跌(如 2024-08-05)→ 瞬间满仓、浮亏巨大(接飞刀)。
优化:    间距绑定 ATR(§1 已并入形状生成器):
  base_step   = clamp( k_atr · ATR/price , step_min(0.5%) , step_max(5%) )
  低波动:    ATR 小 → 间距收窄至 step_min,高频吃极窄震荡。
  暴跌恐慌:  ATR 飙升 → 间距自动放大(下方非对称更宽,step_down = base·(1+asym·vol_pct)):
            放慢接刀速度、降低同等跌幅下的成交格数 → 满仓更慢、浮亏更小、本金被保护。
工程:      ATR 周期 = 14(日线为主);加 hysteresis(滞回带)防间距每根 bar 抖动重布;
          间距变化触发网格重算时,已成交持仓按旧价记账、新挂单用新间距(对账见 v0.1 §4)。
```

### 为什么这是真 edge(有项目证据背书)

- 「间距 ∝ 波动率」在数学上等价于**仓位的波动率目标化**:高波动时少买、低波动时多买,让每单位
  价格区间的风险暴露恒定。这正是线 A 的 L1 用的**反波动率定权**、N1 用的 **σ-scaled barrier** 同源
  思路(线 A `docs/current.md` 已验证反波动率定权是稳健的风险工程,非过拟合旋钮)。
- 它**直接攻 v0.1 最致命的破网尾部**:其余三个优化都在「赚更多」,只有 ③ 在「少亏」,而网格的
  长期生死历来死在尾部那几次暴跌,不是死在日常震荡赚少了。

### 诚实风险

- **ATR 是滞后量**。等 ATR 飙起来,第一波急跌已经发生、你已在窄间距下接了几格刀;③ 调的是**之后**
  的间距,**限制伤害的扩大,但拦不住第一击**。诚实地说,这是「减速带」不是「防撞墙」。
- 动态变间距让网格变成**非均匀阶梯**,已成交格(旧间距)与新挂格(新间距)混存,对账/记账复杂度上升
  ——这是工程风险,不是策略风险,但实盘事故就出在这里。

### kill-test(S-③)

```text
对照:  v0.1 固定间距 vs ATR 弹性间距,跑包含 ≥1 次急跌(2024-08-05 类)的窗口。
判生死: ATR 弹性把暴跌期最大回撤 / 满仓速度显著降低,
        且不在平稳期因间距收得过窄而被成本(maker/滑点)吃掉收益。
关键读数: 暴跌窗口 max_drawdown、满仓所需跌幅、平稳期 net_per_grid 是否仍 ≥ 0.30%。
```

## 5. ④ 生息叠加(DeFi + Grid Alpha Stacking)——分两层,门控最严

> 这是四个里**唯一会改变风险结构、且踩到线 A 已证伪结论**的方向。必须拆成两层,
> 不允许一步到位上 Tier-2。

### Tier-1(干净、可早做):闲置 U 进活期理财

```text
做法:    网格里等待成交的 USDT(尤其高斯分配下远端那批长期挂着的)不闲置,
        转入交易所 Flexible Simple Earn(随时可赎回)赚活期利息(年化 ~2–5%)。
约束:    只用 **Flexible(活期、可即时赎回)**,绝不用 Locked(定期):
        网格要随时拿 U 去成交买单,锁定 = 流动性错配 = 该买时买不进。
诚实定性: 这是**真实的、近乎免费的边际收益**,与网格正交,风险只是交易所托管对手方风险
        (非零、FTX 教训,但属于「你已经把币放在这家交易所」的既有风险,无新增方向暴露)。
判生死:  赎回延迟实测 ≤ 网格下单容忍窗口、且 Earn 收益 > 因偶发赎回延迟漏单的损失 → 可用。
```

### Tier-2(危险、最后做):生息资产当永续保证金跑 1× 网格

```text
设想:    USDT 存 Aave/Earn 生息 → 作全仓保证金 → 跑永续 1× 做多网格 → 同时赚利息 + 网格 + 资金费率。
```

**四个被线 A 证据/常识反驳的硬伤,逐条拆:**

1. **「赚多头资金费率」方向写反了。** 永续**多头在 funding 为正时是付钱、不是收钱**;只有 funding
   为负(熊市/恐慌)时做多才收 funding。牛市 funding 长期为正 → 你这个 1× 做多网格在主升浪里
   **持续支付资金费率**。线 A 的 CARRY(basis-tail 证伪)、L4(跨所 funding 被压到成本地板、每 12h
   翻转)已经把「靠 funding 赚钱」这条路验证为成本墙后为负。**不能把「赚资金费率」当稳定正项。**
2. **「1× 不开杠杆」与永续 + 生息保证金不自洽。** 永续仓位有强平价。若保证金是会波动的生息资产
   (Aave aToken / 脱锚风险的稳定币),或网格满仓被套使浮亏吃掉保证金,**1× 也会被强平** ——
   现货网格最坏是「满仓被套等反弹」,永续网格最坏是「强平归零」,风险性质不同。
3. **流动性错配会引爆清算。** Aave 里的资产要先赎回/解押才能补保证金;急跌时 DeFi gas 飙升、
   提现排队、稳定币脱锚同时发生,**该补保证金时补不进** = 被强平。Tier-1 的 Flexible 约束在这里
   被违反得最彻底。
4. **风险不独立,危机里同向叠加。** 暴跌 → 永续网格满仓浮亏 + funding 剧烈波动 + 稳定币/DeFi 承压
   + Earn 赎回排队,**四件事同时发生**。「一鱼两吃」的两条收益线在尾部同时转负,杠杆化了相关性风险。

```text
Tier-2 门控(全部满足才允许进 paper,否则永不上):
  - 用独立、隔离的保证金(非同一笔在 Aave 生息的本金),避免流动性错配;
  - funding 收益按【做多付正费率】的真实符号建模,不得假设为正项;
  - 强平价距区间下限有足够缓冲(stress 到 2024-08-05 类急跌仍不强平);
  - 稳定币脱锚 + DeFi 提现延迟纳入压力场景。
诚实建议: Tier-2 的额外收益(利息 + 可能为负的 funding)很可能 < 它引入的尾部风险溢价。
        默认**只做 Tier-1**;Tier-2 列为「需所有者显式授权 + 单独工程轮」的远期可选,当前不追。
```

## 7. 验证与上线顺序(每个优化独立增量,一轮只改一处)

**核心纪律**:四个优化**不一次上**。基线(v0.1)先过 S1 持有基线 kill-test,然后**按下表逐个叠加**,
每个都要证明相对「已合入的上一版」有正增量,且不放大尾部风险。

```text
顺序  优化         先验值      kill-test(对照=已合入的上一版)               若不过
─────────────────────────────────────────────────────────────────────────────────
 0    v0.1 基线    —          S1: vs 持有(站上200MA)、S2: maker fill 墙       止盈停
 1    ③ ATR 间距   最高(少亏) S-③: 暴跌窗口回撤↓ 且平稳期 net≥0.30%            回退固定间距
```
