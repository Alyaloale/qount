## 0. 出发点:S1 已经证伪什么、数学上还排除了什么、剩下什么没测

### 0.1 已证伪(S1,2026-06-11,有 artifact)

固定区间长格 + SMA200 滤网,**作为持有的替代品**,在 BTC 2021-01..2026-05 上
0/6 年跑赢 hold-above-200MA,Δ −546.8%。死因 = 踏空(未播种网格牛市大部分在现金)。

### 0.2 数学上已排除、不必再花回测费的构型

S1 的分解给出了量级:**harvest ≈ 3.4%/yr**(扣费后纯波动率收割,这是网格层的真实赚钱能力),
而窗口内 BTC 趋势收益是**两位数到三位数/yr**。由此直接推论:

- **播种网格(S1b)不必单独跑**:播种后任一时刻持仓 ∈ [0%, 100%],均值 ~50%;在趋势年
  少拿的方向收益(几十个点)远大于 harvest(3.4 个点)。播种只是把「踏空」换成「卖飞」,
  量级缺口同样补不上。
- **v0.2 ①高斯/③ATR 不叠加**:形状调制改变 harvest 的效率与尾部,但 harvest 的量级天花板
  在那里(波动率 × 步长 × 资金),差两个数量级的缺口不是形状问题。
- **v0.2 ②追踪不做**:追踪 = 劣化版趋势跟随;要方向暴露,持有更简单且已赢(S1 基线本身)。

> 一句话:**只要窗口由趋势主导,long-only 网格的任何构型都输给持有。** 这不是参数问题,
> 是 harvest 量级 vs 趋势量级的问题。

### 0.3 还活着的、可测的两个假设

| 假设 | 内容 | 为什么还没死 |
|---|---|---|
| **H1 震荡主场(时间维度)** | 存在可识别的震荡 regime;趋势期持有、震荡期网格的**混合构型**或可在全窗口上赢纯持有 | S1 的 harvest 集中在震荡段;但 2025(偏震荡年)网格 +1.1% vs 持有 +7.4% 仍输——先验**不乐观**,需切片定量 |
| **H2 震荡标的(标的维度)** | 存在结构性震荡/无长期趋势的标的(典型:ETHBTC 比价对),网格在其上扣费为正 | S1 只测了 BTCUSDT 一个标的;比价对没有「法币通胀+采用曲线」的长期漂移,是唯一结构上像「震荡主场」的候选 |

**推进方向 = 用三个递进实验(S1d → S1c → S1e)把 H1/H2 判生死;全败则收口。**
预算:全部在 Mac 本地,复用现有 harness,合计 ≤ 1 周;S1e 仅在门后才做。

## 1. S1d — 震荡切片归因(最便宜、最先做,~半天)

**问题**:在「后视镜标注的、对网格最慷慨的震荡窗口」里,网格相对持有到底赚不赚?

**做法**(纯分析,不写新策略代码):

```text
1. 让 run_s1 额外返回 grid_curve / hold_curve(S1Result 加两个字段,增量改动);
2. 后视镜标注 regime:对每个日历月,取「包含它的 91 天窗口」的实现收益 r91 与实现波动:
     chop  : |r91| < 10% 且 年化波动 > 30%   (有波动、没方向 = 网格教科书主场)
     trend : r91 ≥ +10%
     down  : r91 ≤ −10%
   —— 刻意用未来信息标注(等价 S1 的 lookahead_range 哲学):给 H1 最慷慨上界。
3. 在三个桶内分别累计 Δ(grid − hold) 的年化。
```

**预注册判生死(跑前写死)**:

```text
H1 活:chop 桶内 Δ(grid − hold) 年化 ≥ +2%(扣费后)——震荡主场存在,值得做 S1e 混合构型;
H1 死:chop 桶内 Δ ≤ 0 ——连后视镜完美标注的震荡窗里网格都赢不了持有,
       那么任何「事前识别震荡再切网格」的构型(识别必然更差、切换还要付税)更不可能赢。
       S1e 直接取消,H1 关闭。
中间带(0 < Δ < 2%/yr):量级太薄,扛不住 regime 识别误差 + 切换税,按死处理(写明)。
```

> S1d 的价值在「死得便宜」:它用半天时间给 S1e(2–3 天工程)做存在性判定。
> 顺序上**必须先于 S1e**,这是「先证伪再投入」。

## 2. S1c — 标的面板(H2,~1 天含下载)

**问题**:S1 的证伪是 BTC 特有还是普遍?有没有结构性震荡标的让网格活?

**做法**:`scripts/research/grid_b_s1.py` 参数化 symbol,同一 harness、同一慷慨设置
(全窗口 min/max 后视镜区间、maker 扣费、未杠杆)跑面板:

| 标的 | 角色 | 特别说明 |
|---|---|---|
| `ETHUSDT` | 趋势资产复测 | 预期同败,验证普遍性 |
| `SOLUSDT` | 高波动趋势资产 | 高波动 → harvest 上限更高,看缺口是否仍两个数量级 |
| `BNBUSDT` | 趋势资产复测 | 同上 |
| `ETHBTC` | **H2 主角:比价对** | 见下,基线与本位都不同 |

**ETHBTC 的特殊设计(本面板唯一真正的新东西)**:

```text
本位:    BTC。网格的 quote 是 BTC,赚的是「BTC 增益」。
基线 a:  hold-ETH-above-200MA(ETHBTC 日线),BTC 计价 —— 同型对照;
基线 b:  持有 BTC 不动 = 0 —— 机会成本基线。
真实卖点:对一个本就长期持有 BTC 的人,ETHBTC 网格若扣费后 BTC 本位为正,
         就是一层「BTC 生息」,不需要赢基线 a,只需要赢基线 b(>0)且非单年扛。
诊断跑法:带 SMA200 滤网跑一遍(主),不带滤网再跑一遍(诊断:比价对长期下行段
         滤网会长期 PAUSED,看「能玩的时间」有多少)。
风险注记:ETHBTC 盘口深度远薄于 USDT 对,若过门,S2 maker-fill 压力测试权重加倍。
```

**预注册判生死**:

```text
USDT 趋势对:  与 BTC 同标准(vs hold-above-200MA,分年)。预期全败;若有标的意外
              Δ>0 且非单年扛 → 单独复查(先怀疑数据/区间运气,再怀疑结论)。
ETHBTC:       扣费后 BTC 本位总收益 > 0,且 ≥4/6 年为正(不许单年扛),
              且 maxDD(BTC 本位)< harvest 总量(赚的钱要够付一次最深回撤)
              → H2 活,进 §4 后续门(S2/S3);否则 H2 死。
```

## 3. S1e — 三态混合构型(仅 H1 过门后做,~2–3 天)

> **门控:S1d 判 H1 活才动工。** H1 死则本节整体取消,不留「以后再试」的尾巴。

**构型**(接受「网格不创造方向 alpha」,只让网格填趋势策略的空窗):

```text
三态 regime(日线收盘评估,沿用 confirm_bars=2 防假突破):
  uptrend : close > SMA200 且 r90 ≥ +15%   → 满仓持有(与基线行为一致)
  range   : close > SMA200 且 |r90| < 15%  → 持仓改造成播种网格:上方挂卖梯、下方挂买梯
  below   : close < SMA200(确认)          → 清仓空仓(同 v0.1 PAUSED)

切换成本显式建模:uptrend↔range 的建格/撤格、range→below 的清仓全按实际单数计费,
taker 部分按 taker;统计 switch_count 与 whipsaw 成本单列。
```

**预注册判生死**:

```text
vs hold-above-200MA(同一基线,全窗口 2021-01..2026-05):
  过:Δ > 0 且 ≥3/6 年为正 且 切换税(whipsaw 成本)< chop 桶 harvest 的 1/3
      → 进 S3(r90 阈值 10%/15%/20% + chop 定义敏感度扫描,借线 A DSR/PBO harness)
      → 过 S3 再进 S2(maker 墙)→ S4 paper(跑满 ≥1 次完整 range↔uptrend 切换)。
  不过:H1 关闭。混合构型是 H1 的最优操作化,它败 = 时间维度主场不存在。
```

**先验(诚实写下,防自我感动)**:S1d 给的是后视镜上界,S1e 是事前识别 + 付切换税的现实版,
通常只能拿到上界的一部分。若 S1d 只是勉强过 +2%/yr,S1e 大概率死;心理预期按「确认性证伪」设。
