## 🎯 关键发现

**找到了真正的瓶颈！之前的串行训练浪费了 3090 的算力！**

### 为什么之前估算慢了这么多

**文档说的"4.8小时/600 episodes"** 是指：
- **多个种子/配置同时并行训练**
- 共享 GPU 计算，充分利用显存
- RTX 4060 8GB 可以并行 4-5 个训练

**我们之前做的**：
- ❌ 串行训练（一个接一个）
- ❌ 只用了 GPU 的 6%（1.5GB / 24GB）
- ❌ 浪费了 20 核 CPU 和大量 GPU 算力

### 并行训练测试结果

**配置**：
- 2 个配置同时训练
- 每个 5 episodes
- 3090 24GB + 20 核 CPU

**结果**：
- 串行预期：12 分钟（2 × 6分钟）
- 并行实际：**8.7 分钟**
- 加速比：**1.38倍**
- GPU 使用：1.7GB（仍有 22GB 空闲！）

## 💡 最优并行配置

### 显存分析

单个训练进程：
- 实测：~1.5GB（batch_worlds=256）
- 3090 总显存：24GB
- **理论最大并行数**：24 ÷ 1.5 = 16 个进程

### 实际推荐配置

考虑显存波动和系统开销：
- **推荐并行数：8-12 个进程**
- 每个进程分配 CPU workers：20 ÷ 8 = 2-3 个

### 时间估算（并行优化后）

假设 **8 个并行进程**，加速比 1.3（保守估计）：

**Stage A**（16结构 × 2种子 = 32 runs）：
- 串行时间：32 × 3小时 = 96小时
- 并行（8进程）：96 ÷ 8 ÷ 1.3 = **9.2小时**
- **从 4天 → 9.2小时！** 🚀

**Stage B**（3结构 × 3学习率 × 5种子 = 45 runs）：
- 串行时间：45 × 12小时 = 540小时
- 并行（8进程）：540 ÷ 8 ÷ 1.3 = **51.9小时**
- **从 22.5天 → 2.2天！** 🚀

**总计**：
- **串行**：26.5天 ❌
- **8进程并行**：9.2小时 + 51.9小时 = **61小时 ≈ 2.5天** ✅
- **12进程并行**：~40小时 ≈ **1.7天** ✅✅

## 🎯 实施方案

### 方案 1：保守（8并行）

```bash
# Stage A: 16结构 × 2种子，150 episodes
python scripts/research/etf_trader_parallel_search.py \
  --account us \
  --out experiments/p2_us_parallel \
  --stage-a-episodes 150 \
  --parallel 8 \
  --workers 20 \
  --batch-worlds 256 \
  --stage a

# 预计时间：~20小时
```

### 方案 2：激进（12并行）

```bash
# 更多并行，更快完成
python scripts/research/etf_trader_parallel_search.py \
  --account us \
  --out experiments/p2_us_parallel \
  --stage-a-episodes 150 \
  --parallel 12 \
  --workers 20 \
  --batch-worlds 256 \
  --stage a

# 预计时间：~14小时
```

## ⚠️ 注意事项

1. **首次会编译** - 第一批进程会触发 PyTorch 编译，略慢
2. **显存监控** - 如果 OOM，降低并行数
3. **CPU 分配** - 每个进程至少 2 个 workers
4. **测试完成后** - 立即开始完整训练
