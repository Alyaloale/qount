## 当前性能分析

**实测数据**（batch_worlds=256）：
- Episode 0: 241秒（首次 torch.compile）
- Episode 1+: ~72秒（40秒生成 + 32秒训练）

**瓶颈识别**：
1. 世界生成：40秒（CPU，需C++内核）
2. GPU训练：32秒（已有 prefetch 重叠）
3. 首次编译：~130秒（一次性）

## 优化策略

### 1. C++ 内核加速（最重要）

**问题**：C++ 生成器未上传到服务器，服务器会第一次运行时自动编译到 `~/.cache/qount/native`

**优化**：
- 确保服务器有 C++ 编译器（g++ 或 clang）
- 首次编译后会缓存，后续复用
- 预期加速：**70倍**（文档数据）
- 世界生成：40秒 → ~0.6秒

### 2. batch_worlds 优化

**当前**：256 worlds
**显存使用**：
- 256 worlds: ~1.4GB（当前）
- 512 worlds: ~2.8GB（估算）
- 1024 worlds: ~5.6GB（估算）
- 3090 有 24GB，可用 ~20GB

**建议**：
- 测试 512 → 1024 → 2048
- 找到最优吞吐量（显存 vs 效率）

### 3. workers 数量

**当前**：8（默认）或 32（过多）
**分析**：
- 世界生成在 prefetch 期间完成
- workers 太多会导致内存压力和上下文切换
- C++ 内核加速后，世界生成变快，workers 需求降低

**建议**：
- 开始用 8-16 workers
- C++ 加速后可能只需 4-8 workers

### 4. 时间估算（优化后）

**假设**：
- C++ 加速：世界生成 40秒 → 0.6秒
- batch_worlds 加倍：512（训练时间增加 ~20%）
- prefetch 完全重叠

**单个配置**（150 episodes）：
- Episode 0: ~150秒（编译）
- Episode 1-149: ~38秒（0.6生成 + 38训练）
- 总计：150 + 148×38 = **5,774秒 ≈ 1.6小时**

**Stage A**（32 runs）：
- 串行：32 × 1.6小时 = **51小时 ≈ 2.1天**
- 但 C++ 编译是一次性的！

**实际更快**：
- 只有第一个run编译 C++ + PyTorch（~5分钟）
- 后续 run 复用编译缓存
- 每个 run 实际只需 148×38秒 ≈ **1.5小时**
- 总计：32 × 1.5小时 = **48小时 ≈ 2天**
