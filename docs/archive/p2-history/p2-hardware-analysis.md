## 监控数据解读

### 当前状态（单进程训练）

**GPU 利用率模式**：
```
时间线：
├─ 首次编译：GPU 90% 持续
├─ Episode 1：GPU 20%（prefetch 中）
├─ Episode 2+：
│   ├─ 世界生成 40秒：GPU ~10%
│   └─ GPU 训练 32秒：GPU ~90%
```

**资源利用**：
- GPU 利用率：**平均 30-40%** ❌
- 显存：2GB / 24GB = **8%** ❌
- CPU：1500% / 2000% = **75%** ✓

**结论**：GPU 和显存严重浪费！

## 为什么 GPU 利用率低

### 问题：世界生成是 CPU 密集型

```
单进程时间线：
[世界生成 40s - CPU工作] [GPU训练 32s - GPU工作]
└─ GPU 闲置 40秒       └─ GPU 忙 32秒

GPU 利用率 = 32 / (40+32) = 44%
```

### 解决：多进程重叠

```
16 个进程并行：
进程1:  [生成40s][训练32s]
进程2:      [生成40s][训练32s]
进程3:          [生成40s][训练32s]
...
进程16:                  ...[生成40s][训练32s]

GPU 几乎一直有进程在训练！
利用率 → 80-90%
```

## 硬件容量分析

### 显存容量

**单进程使用**：~2GB（实测）
**可并行数**：24GB ÷ 2GB = **12 个进程**（保守）

实际可能更多：
- 显存峰值 2GB，平均 1.5GB
- 可以跑 **16 个进程**（1.5GB × 16 = 24GB）

### CPU 容量

**20 核 CPU**：
- 世界生成：8 workers/进程（CPU 密集）
- 如果 16 个进程，需要 128 workers
- 但实际：workers 可以动态共享

**建议配置**：
- 16 个并行进程
- 总 workers = 20（让所有进程共享）
- 每个进程平均分到 1-2 个 worker

## 优化后的时间估算

### 当前（8 并行，效率 70%）

**Stage A**（32 configs × 150 ep）：
- 串行：32 × 3h = 96h
- 8并行：96h ÷ 8 ÷ 0.7 = **17h**

**Stage B**（45 configs × 600 ep）：
- 串行：45 × 12h = 540h
- 8并行：540h ÷ 8 ÷ 0.7 = **96h**

**总计：113h ≈ 4.7天**

### 优化后（16 并行，效率 65%）

效率略降（更多进程竞争资源），但总体更快：

**Stage A**：
- 16并行：96h ÷ 16 ÷ 0.65 = **9.2h**

**Stage B**：
- 16并行：540h ÷ 16 ÷ 0.65 = **52h**

**总计：61h ≈ 2.5天**

### 使用文档配置（30/100 ep）

**Stage A**（32 × 0.6h）：
- 16并行：32 × 0.6h ÷ 16 ÷ 0.65 = **1.8h**

**Stage B**（45 × 2h）：
- 16并行：45 × 2h ÷ 16 ÷ 0.65 = **8.6h**

**总计：10.4h**
